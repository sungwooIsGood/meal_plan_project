# Git Workflow Rules

## 핵심 원칙

작업이 완료되면 **현재 브랜치에 커밋하고 푸시**까지 끝낸다. 로컬에만 남기지 않는다.

---

## 1. 브랜치 정책

- **현재 체크아웃된 브랜치 기준**으로 커밋·푸시한다.
- 작업 도중 임의로 브랜치를 바꾸거나 새 브랜치를 만들지 않는다 — 사용자가 명시적으로 지시한 경우에만.
- `main` / `master` / `develop` 같은 보호 브랜치에 직접 커밋·푸시는 사용자가 명시적으로 허용한 경우에만 수행.

---

## 2. 커밋 규칙

### 무엇을 커밋하나

- 작업 단위로 의미 있게 묶어서 커밋. 한 PR = 한 커밋이 아니어도 좋지만, 한 커밋이 한 가지 변경 의도만 담도록 한다.
- 관련 없는 변경을 한 커밋에 섞지 않는다.

### 스테이징

- `git add .` 보다 **명시적 파일/경로 스테이징**을 우선. 의도치 않은 파일이 섞이는 것을 방지.
- 비밀 정보가 들어갈 수 있는 파일(`.env`, `*.key`, `credentials*` 등)은 스테이징 전에 반드시 확인.

### 커밋 메시지

- 한국어 또는 영어로 일관되게.
- 제목 줄(50자 내외) + 본문(필요 시) 형식.
- Conventional Commits 권장:
  - `feat: 주문 생성 UseCase 추가`
  - `fix: 재고 차감 동시성 버그 수정`
  - `test: 결제 도메인 환불 시나리오 테스트 추가`
  - `refactor: 결제 어그리거트 분리`
  - `docs: 백엔드 아키텍처 룰 문서화`

---

## 3. 푸시 규칙

- 커밋 후 **현재 브랜치를 원격으로 푸시**한다.
- 신규 브랜치라면 업스트림 설정 포함: `git push -u origin <current-branch>`.
- **금지**: `--force`, `--force-with-lease` 푸시는 사용자가 명시적으로 요청한 경우에만.

---

## 4. 표준 절차

```bash
# 1) 현재 브랜치 확인
git branch --show-current

# 2) 변경사항 검토
git status
git diff

# 3) 의도된 파일만 스테이징
git add <files>

# 4) 커밋
git commit -m "<type>: <message>"

# 5) 현재 브랜치로 푸시
git push        # 업스트림이 이미 있는 경우
# 또는
git push -u origin "$(git branch --show-current)"   # 신규 브랜치
```

---

## 5. 안전 가드

- pre-commit / pre-push 훅은 **건너뛰지 않는다** (`--no-verify` 금지). 훅이 추가한 변경은 별도 커밋으로 잡는다.
- `git config` 변경 금지.
- `git reset --hard`, `git clean -f`, `git branch -D`는 사용자 명시 허가 후에만.
- 푸시 실패 시(예: non-fast-forward) 자동 force 푸시 금지 → 사용자에게 보고하고 지시 대기.

---

## 6. 완료 보고

작업 완료 시 다음을 보고에 포함:

- 현재 브랜치명
- 커밋 해시(들)와 메시지
- 푸시 완료 여부 및 원격 추적 브랜치
