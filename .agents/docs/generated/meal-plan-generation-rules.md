# 식단 생성(랜덤 메뉴) API 규칙 문서

> 저장된 메뉴 풀을 바탕으로 한 달치(또는 지정 범위) 식단을 자동 생성하는 API의 규칙을 설명한다.
> 사용자가 요청 body로 무엇을 보내느냐에 따라 규칙이 어떻게 달라지는지 포함한다. 실제 구현 기준.

---

## 1. 엔드포인트

```
POST /api/meal-plans/generate/{year}/{month}     예: /api/meal-plans/generate/2026/06
```

- `{year}/{month}` (path): 생성할 년·월. 월은 1~12. (잘못되면 400 `INVALID_YEAR_MONTH`)
- **요청 body는 선택**이다. body가 없거나 비면 아래 "기본 규칙"으로 생성한다.
- 생성에 쓰는 메뉴는 **이미 저장된 식단표들의 메뉴 풀**이다. 저장된 데이터가 없으면 422.

규칙 안내만 따로 보고 싶으면:
```
GET /api/meal-plans/generation-rules     → 기본 규칙을 JSON으로 반환 (프론트 표시용)
```

---

## 2. 기본 규칙 (요구사항을 안 보냈을 때)

### 2-1. 하루 한 끼 구성
- 주식(STAPLE_FOOD) 1개
- 국/탕(SOUP) 1개
- 주찬(MAIN_DISH) 1개
- 부찬(SIDE_DISH) 1개 또는 2개
- 김치(KIMCHI) 1개
- 후식(DESSERT)/음료(BEVERAGE)는 선택

### 2-2. 중복 금지 규칙 (핵심)
중복 금지 기간은 **조식·중식·석식을 합친 "전체 타임라인" 기준**이다. 끼니가 달라도 동일하게 적용된다.

| 카테고리 | 중복 금지 기간 | 의미 |
|---|---|---|
| 주식(STAPLE_FOOD) | **7일** | 같은 밥이 7일 이내 재등장 금지 |
| 국/탕(SOUP) | **7일** | 같은 국이 7일 이내 재등장 금지 |
| 김치(KIMCHI) | **4일** | 같은 김치가 4일 이내 재등장 금지 |
| 부찬(SIDE_DISH) | **14일(2주)** | 같은 부찬이 2주 이내 재등장 금지 |
| 주찬(MAIN_DISH) | **30일** | 한 달 내 최대한 중복 회피 |

> 예) 6월 1일 조식에 흰쌀밥이 나오면, 6월 7일까지는 **어느 끼니에도** 흰쌀밥이 다시 나오지 않는다.
> (1일 ↔ 8일은 간격 7이라 허용)

### 2-3. 같은 날 끼니 간 규칙
- **같은 날 안에서는 끼니 간 메뉴가 겹치지 않는다.** 조식에 쓴 메뉴는 그날 중식·석식에 나오지 않는다. (반대도 동일)
- 단, **다른 날**의 끼니 간에는 위 "기간 규칙"만 적용된다 (예: 주찬 30일 등).

---

## 3. 요청 body 옵션과 규칙 변화

body는 모두 선택 필드다. 각 필드가 규칙에 어떻게 작용하는지:

```json
{
  "startDay": 1,
  "endDay": 30,
  "mealTypes": ["BREAKFAST", "LUNCH", "DINNER"],
  "includeWeekends": true,
  "requirements": "매운 음식 위주로, 부찬은 2개씩",
  "mustIncludeMenus": ["제육볶음", "미역국"]
}
```

| 필드 | 안 보냈을 때(기본) | 보냈을 때 |
|---|---|---|
| `startDay` | 그 달 1일 | 지정한 시작일부터 |
| `endDay` | 그 달 말일 | 지정한 종료일까지 |
| `mealTypes` | 조식(BREAKFAST)만 | 지정한 끼니만 생성 (BREAKFAST/LUNCH/DINNER 복수 가능) |
| `includeWeekends` | true (주말 포함) | true=주말 포함 / false=평일(월~금)만 생성 |
| `requirements` | **기본 구성·규칙** 그대로 | 자유 텍스트 요구사항을 추가 반영 (예: "매운 음식 위주", "부찬 2개") |
| `mustIncludeMenus` | 없음 | 지정 메뉴를 가능한 한 배치 |

### 날짜 범위 (startDay/endDay)
- 범위가 그 달을 벗어나거나 start > end면 400.

### 주말 포함 (includeWeekends)
- `true`(기본): 토·일도 식단을 생성한다.
- `false`: 토·일을 제외하고 평일(월~금)만 생성한다.

### 끼니 (mealTypes)
- 여러 개 선택 가능. 선택한 끼니에 대해서만 식단을 만든다.
- 조식·중식·석식을 모두 선택하면, 위 "같은 날 끼니 간 중복 금지"가 함께 적용된다.

### 요구사항 (requirements)
- 자유 텍스트. 없으면 기본 규칙만 적용.
- 있으면 그 내용을 우선 반영하되, **중복 금지 규칙(2-2)·같은 날 규칙(2-3)은 항상 강제**된다. (요구사항이 규칙을 깨뜨리지 못함)

### 꼭 포함할 메뉴 (mustIncludeMenus)
- 지정한 메뉴를 결과에 가능한 한 포함한다. (단, 메뉴 풀에 존재해야 하고 중복 규칙 범위 내에서 배치)

## 4. 생성은 어떻게 이뤄지나 (동작 원리)

```
저장된 메뉴 풀 수집(카테고리별)
   │
   ├─ ① AI 생성 시도 (OpenAI)        ← 풀·규칙·요구사항을 프롬프트로 전달
   │       │
   │       ▼
   ├─ ② 결정론적 검증                ← 생성 결과가 중복 규칙을 지키는지 코드로 검사
   │       │
   │       ├─ 위반 0건 → 그대로 채택 (usedAi=true)
   │       └─ 위반 있음 ↓
   │
   └─ ③ 결정론적 생성기로 대체        ← 규칙을 보장하며 직접 생성 (usedAi=false)
```

핵심 원칙: **규칙 준수는 AI가 아니라 코드가 최종 보장한다.**
- AI(OpenAI)는 "더 자연스러운 초안"을 만드는 역할이다.
- AI 결과라도 **결정론적 검증기**(중복 규칙 검사)를 통과해야 채택된다.
- 통과 못 하거나 AI가 꺼져 있으면, 규칙을 보장하는 **결정론적 생성기**가 메뉴 풀에서 직접 골라 만든다.
- AI가 풀에 없는 메뉴를 지어내면(환각) 버린다. 저장된 메뉴 풀 안의 것만 사용한다.

---

## 5. 후보 풀 — AI에 무엇을, 얼마나 주나 (토큰 상한)

저장된 메뉴 전부를 AI에 주지 않는다. **카테고리별로 후보 N종만 추려서** 전달한다.
전국 규모로 데이터가 쌓여도 AI 프롬프트(토큰) 크기를 일정하게 유지하기 위함이다.

### 언제·어디서 추리나
- **추리는 시점**: 저장(import) 때가 아니라 **생성 요청(read-time) 때**. (저장은 원본·빈도를 보존)
- **추리는 곳**: MongoDB **aggregation**으로 DB가 집계한다. 애플리케이션이 전체를 메모리에 올려 세지 않는다.
  → DB가 `메뉴 펼치기 → 메뉴별 빈도 집계 → 정렬 → 상위 N` 을 처리하고, 서버는 결과(상위 N + 빈도)만 받는다.

### 인기 + 랜덤 섞기 (다양성)
상위 인기만 뽑으면 매번 같은 메뉴만 나오므로, **인기 상위 + 랜덤 샘플**을 섞는다.

```
카테고리별 후보 N종 = 인기 상위 60% + 랜덤 40%
   ├─ 인기 상위 60% : 빈도(많이 쓰인 순) 상위        ← 검증된 메뉴(품질)
   └─ 랜덤 40%      : 인기 상위를 제외한 나머지에서 무작위 추출  ← 다양성·롱테일
```
- 랜덤 추출도 MongoDB(`$sample`)가 처리한다. 요청마다 랜덤 부분이 달라져 **매번 다른 식단**이 나온다.
- 인기 없는 메뉴도 랜덤 몫을 통해 가끔 뽑힌다.

### 카테고리별 후보 개수 (N)
조식·중식·석식 3끼 + 주말 포함(최대 31일×3끼 = 93배치)까지 고려해, 중복 금지 기간을 지킬 수 있도록 넉넉히 잡는다.

| 카테고리 | 후보 N | 인기 60% | 랜덤 40% |
|---|---|---|---|
| 부찬(SIDE_DISH) | 120 | 72 | 48 |
| 주찬(MAIN_DISH) | 90 | 54 | 36 |
| 국/탕(SOUP) | 60 | 36 | 24 |
| 주식(STAPLE_FOOD) | 50 | 30 | 20 |
| 후식(DESSERT) | 40 | 24 | 16 |
| 김치(KIMCHI) | 30 | 18 | 12 |
| 음료(BEVERAGE) | 30 | 18 | 12 |
| **합계** | **약 420종** | | |

- 전국에 메뉴가 수만 종이어도 **AI엔 항상 약 420종만** 전달된다 → 토큰 상한 고정.
- **풀의 고유 메뉴가 N보다 적으면** 인기/랜덤 구분 없이 **있는 것 전부** 사용한다. (예: 김치 7종뿐이면 7종 다)
- 비율(`POPULAR_RATIO=0.6`)과 개수는 코드 상수(`GenerationRules`)로 관리하며 튜닝 가능하다.

> 비율·개수의 원천(Source of Truth)은 `GenerationRules.java` 다. 이 표와 코드가 어긋나면 코드가 기준.

## 6. 메뉴 풀이 부족하면? (중요)

규칙을 지키려면 카테고리별로 **충분히 다양한 메뉴**가 있어야 한다.
- 예) 주찬 30일 중복 금지 + 30일치 생성 → 주찬이 최소 30종 필요. 풀이 20종뿐이면 일부 중복이 불가피.

이때 동작:
- 생성은 **계속 진행**한다(거부하지 않음). 가능한 한 규칙을 지키되, 불가피한 중복은 허용한다.
- 응답의 `ruleViolations`에 **어떤 규칙이 왜 깨졌는지** 목록으로 알려준다.
  (예: `"[주찬] '제육볶음'이 20일 간격으로 재등장 — 규칙: 끼니 통합 30일 내 금지"`)
- 즉, "메뉴가 부족하면 알려주되 생성은 해준다"는 정책이다.

## 7. 응답 형태

```json
{
  "totalMeals": 30,
  "usedAi": true,
  "ruleViolations": [],
  "days": [
    {
      "date": "2026-06-01",
      "meals": [
        {
          "mealType": "BREAKFAST",
          "itemsByCategory": {
            "STAPLE_FOOD": ["흰쌀밥"],
            "SOUP": ["미역국"],
            "MAIN_DISH": ["제육볶음"],
            "SIDE_DISH": ["시금치나물"],
            "KIMCHI": ["배추김치"]
          }
        }
      ]
    }
  ]
}
```

| 필드 | 의미 |
|---|---|
| `totalMeals` | 생성된 끼니 수 (날짜 수 × 선택 끼니 수) |
| `usedAi` | true=AI 생성 채택, false=결정론적 생성기 사용 |
| `ruleViolations` | 규칙 위반 목록. **비어 있으면 규칙 완전 준수** |
| `days[].meals[].itemsByCategory` | 끼니별 카테고리 → 메뉴명 목록 |

---

## 8. 에러

| 상황 | 응답 |
|---|---|
| 월이 1~12 범위 밖 | 400 `INVALID_YEAR_MONTH` |
| 날짜 범위가 그 달을 벗어남 / start>end | 400 `INVALID_ARGUMENT` |
| 저장된 식단 데이터가 없음(메뉴 풀 비어 있음) | 422 `NOT_MEAL_PLAN_CONTENT` |

---

## 9. 호출 예시

```bash
# 기본 규칙으로 2026년 6월 전체(조식) 생성
curl -i -X POST http://localhost:8080/api/meal-plans/generate/2026/06

# 6월 1~7일, 조식+중식+석식, 요구사항·필수메뉴 지정
curl -i -X POST http://localhost:8080/api/meal-plans/generate/2026/06 \
  -H "Content-Type: application/json" \
  -d '{
        "startDay": 1,
        "endDay": 7,
        "mealTypes": ["BREAKFAST","LUNCH","DINNER"],
        "requirements": "매운 음식 위주, 부찬 2개",
        "mustIncludeMenus": ["제육볶음"]
      }'

# 기본 규칙 안내 조회 (프론트 표시용)
curl -i http://localhost:8080/api/meal-plans/generation-rules
```
